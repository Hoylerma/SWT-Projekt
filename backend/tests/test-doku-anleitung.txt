# Unit-Tests der Domänenmodelle (Lab 4, Aufgabe 4.3)

Dieses Dokument beschreibt die Unit-Tests für die Entitäten `Rezept` und `Zutatenzeile`, was sie prüfen und wie man sie ausführt. Den Aufbau der Entitäten beschreibt [spec/data-model.md](spec/data-model.md), die Einrichtung [setup.md](setup.md).

> KI-Hinweis: Teile dieses Dokuments und der Tests wurden mit KI-Unterstützung (Claude) erstellt und vom Team geprüft.

## Eingesetzte Werkzeuge

| Zweck | Werkzeug |
|---|---|
| Test-Framework | pytest (`backend/requirements-dev.txt`) |
| Abhängigkeiten installieren | pip mit `requirements-dev.txt` |
| Konfiguration | `backend/pytest.ini` |
| Testprofil | `APP_ENV=test`, wird in `tests/conftest.py` gesetzt |

Python hat kein eigenes Build-Tool wie Maven oder Gradle. `pip` und `pytest` übernehmen diese Rolle: ein Befehl, keine externen Dienste.

## Tests ausführen

Voraussetzung: Python 3.12 oder neuer. Eine Datenbank oder Docker braucht man nicht.

```bash
cd backend
python -m venv .venv
# Windows:   .venv\Scripts\activate
# Linux/Mac: source .venv/bin/activate
pip install -r requirements-dev.txt

pytest tests/unit          # nur die Unit-Tests dieser Aufgabe
pytest tests/unit -v       # jeder Test einzeln mit Namen
pytest                     # zusätzlich der Smoke-Test (Aufgabe 4.1)
```

Mit Docker, ohne eigene Python-Installation:

```bash
docker run --rm -v "$(pwd):/app" -w /app python:3.12-slim \
  sh -c "pip install -q -r requirements-dev.txt && pytest tests/unit -v"
```

**Erwartetes Ergebnis:** `17 passed` für die Unit-Tests, `18 passed` mit dem Smoke-Test. Eine Warnung von Starlette zu `httpx` stammt vom Smoke-Test und ist harmlos.

## Abgrenzung

Die Unit-Tests laufen ohne Datenbank und ohne Aufruf der externen Abhängigkeit (Kalender-Dienst). Sie erzeugen die Entitäten nur im Speicher. Der Smoke-Test liegt getrennt unter `tests/smoke/`.

## Aufbau

| Datei | Gegenstand | Tests |
|---|---|---|
| `tests/unit/test_rezept.py` | Entität `Rezept` | 6 |
| `tests/unit/test_zutatenzeile.py` | Entität `Zutatenzeile` | 8 |
| `tests/unit/test_beziehung_rezept_zutat.py` | Beziehung 1:n | 3 |

## Was geprüft wird

Die vier Prüfungen aus der Aufgabe sind so abgedeckt:

1. **Gültige Erzeugung liefert die gesetzten Werte.** Ein Rezept mit Name und Portionen und eine Zutatenzeile mit Name, Menge und Einheit haben nach dem Anlegen genau diese Werte.
2. **Fehlende Pflichtfelder werden abgelehnt.** Fehlt ein Pflichtfeld, wirft die Entität einen `ValueError`.

   | Entität | Pflichtfeld | Abgelehnt |
   |---|---|---|
   | Rezept | name | `None`, leer, nur Leerzeichen |
   | Rezept | portionen | `None` |
   | Zutatenzeile | name | `None`, leer, nur Leerzeichen |
   | Zutatenzeile | menge | `None` |
   | Zutatenzeile | einheit | `None`, leer, nur Leerzeichen |

3. **Beziehung.** Eine hinzugefügte Zutatenzeile ist über `rezept.zutaten` abrufbar, und `zeile.rezept` zeigt auf das Rezept zurück. Setzt man `zeile.rezept` von Hand, erscheint die Zeile ebenfalls in der Liste des Rezepts.
4. **Hilfsmethode.** `Rezept.add_zutat` hat einen eigenen Test: Sie hängt die Zeile an das Rezept an und gibt sie zurück.

## Bei Änderungen

Neue Regeln für die Entitäten gehören in `backend/app/models.py`, dazu jeweils ein Test in der passenden Datei unter `tests/unit/`.
